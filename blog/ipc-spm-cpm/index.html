HOW MULTI-CORE PROCESSORS TALK USING SCRATCHPAD AND COMMON PACKET MEMORY

When multiple processor cores live on the same chip, they need to share messages without slowing down or crashing into each other. Here is the simple, complete guide to IPC (Inter-Process Communication), SPM (Scratchpad Memory), and CPM (Common Packet Memory), including exactly what the sender and receiver must check, do, and update. No complicated code required!

1. WHAT IS IPC, SPM & CPM?

Before looking at checks and pointers, let's understand the basic meaning of each term in plain English:

💬 What is IPC?

IPC stands for Inter-Process Communication (or Inter-Core Communication). It simply means: how two or more processor cores on the same chip talk, share data, and send messages to each other.

📝 What is SPM?

SPM stands for Scratchpad Memory. Think of it as a core's private, personal notepad. It sits right next to the core. Only that core can read and write to it with instant, zero-delay speed. Other cores cannot freely write to it without permission or a dedicated transfer.

📬 What is CPM?

CPM stands for Common Packet Memory. Think of it as a shared neighborhood mailbox placed right in the middle between both cores. Both the sender and receiver cores can see and access this shared memory directly to drop off and pick up message packets.

[ CORE A (Sender) ] [ CORE B (Receiver) ] | | +-----------+ +-----------+ | Core A's | | Core B's | | Local SPM | (Private Notepads) | Local SPM | +-----------+ +-----------+ | | \===================+=============================/ | +---------------------+ | CPM | | (Shared Mailbox) | <-- Both Cores Can Access! +---------------------+
💡 The Big Difference: In SPM, each core works in its own private memory room and copies data across. In CPM, both cores meet in a common shared room (the mailbox) to exchange messages!

2. SENDER'S PERSPECTIVE: WHAT TO CHECK & WHAT TO DO

When Core A wants to send data to Core B, what are all the things the sender must check and do?

A. What the Sender Must Check Before Sending:

  • 1. The Full Check (Most Important!): The sender MUST check whether the buffer has free slots. If the buffer is full, the sender must STOP and wait. If it writes to a full buffer, it will overwrite unread messages and destroy data!
  • 2. Message Validity & Size: Check that the data packet is ready, not corrupted, and fits within the allowed slot size (e.g. 64 bytes or 256 bytes).
  • 3. Channel Ready State: Check that the communication channel is initialized and enabled.

B. What the Sender Must Do When Sending:

  • In SPM: The sender prepares the message inside its own local SPM. Then it copies the data over to the receiver's SPM area (or triggers a DMA hardware copy).
  • In CPM: The sender writes the message directly into the next free slot inside the shared CPM memory (at the current Head position).
  • Update the Head Pointer: Once the data is completely written, the sender increments the Head pointer to point to the next slot: Head = (Head + 1) % Total_Slots.
  • Notify the Receiver: Send an interrupt signal or set a "Data Ready" flag so the receiver knows a new message has arrived.

3. RECEIVER'S PERSPECTIVE: WHAT TO CHECK & WHAT TO DO

When Core B is waiting to receive data from Core A, what are all the things the receiver must check and do?

A. What the Receiver Must Check Before Reading:

  • 1. The Empty Check (Most Important!): The receiver MUST check whether there is actually any new data to read. If the buffer is empty (Head == Tail), the receiver must STOP and wait. If it reads from an empty buffer, it will read old, stale junk data!
  • 2. Packet Header / Checksum: Check the packet magic number or checksum to ensure the data is complete and not corrupted.

B. What the Receiver Must Do When Receiving:

  • In SPM: The receiver reads the incoming message directly from its own local SPM where it was delivered, and starts processing it immediately.
  • In CPM: The receiver reads the message packet directly from the shared CPM slot (at the current Tail position), copying it into its private registers or local variables.
  • Process the Data: Execute whatever work the message asked for (e.g., sensor calculations, motor control, or graphics rendering).
  • Update the Tail Pointer: Once the message is safely consumed, the receiver increments the Tail pointer: Tail = (Tail + 1) % Total_Slots. This officially frees up the slot so the sender can use it again!
  • Optional Ack / Signal: If required, notify the sender that the slot is now free.

4. TABLE: SENDER & RECEIVER IN SPM VS. CPM

Here is the complete side-by-side comparison of sender and receiver actions in both memory models:

Perspective In SPM (Scratchpad Memory) In CPM (Common Packet Memory) Why This is Done
Sender: What to Check Check if remote core's SPM buffer has space; check if receiver is ready. Check the Full Check Condition in the shared CPM queue. To prevent writing over unread data (buffer overflow).
Sender: What to Do Builds packet in local SPM → copies data into receiver's SPM area → updates local write index. Writes packet directly into the shared CPM slot → updates shared Head pointer. To safely store the new message and advance the write queue.
Receiver: What to Check Check if new data arrived in its local SPM (via interrupt or flag). Check the Empty Check Condition in the shared CPM queue (Head != Tail). To prevent reading old, expired junk data (buffer underflow).
Receiver: What to Do Reads packet from its own local SPM → processes data → clears the local flag/slot. Reads packet from shared CPM slot → processes data → updates shared Tail pointer. To consume the message and mark the slot as free for future writes.

5. FULL CHECK & EMPTY CHECK CONDITIONS

In both SPM and CPM, messages are usually organized as a Circular Ring Buffer (a circular queue of slots, say 8 slots numbered 0 to 7). Two markers keep track of where we are:

  • Head: Where the sender will write the next message.
  • Tail: Where the receiver will read the next message.
[Slot 0] <-- Tail (Receiver reads here) [Slot 1] (Filled with unread message) [Slot 2] (Filled with unread message) [Slot 3] <-- Head (Sender writes next message here) [Slot 4] (Empty) [Slot 5] (Empty) [Slot 6] (Empty) [Slot 7] (Empty)

🔴 1. The Full Check Condition (Buffer Full)

When does the sender know the queue is FULL?
When moving the Head forward by one step would make it run into Tail:

FULL CHECK FORMULA: (Head + 1) % Buffer_Size == Tail
⚠️ Why Full Check is Critical: If the sender writes when (Head + 1) % Buffer_Size == Tail, it will overwrite the exact message that the receiver hasn't read yet! The sender must wait until the receiver moves Tail forward.

🟢 2. The Empty Check Condition (Buffer Empty)

When does the receiver know the queue is EMPTY?
When Head has not moved past Tail, meaning no new unread messages were added:

EMPTY CHECK FORMULA: Head == Tail
💡 Why Empty Check is Critical: If Head == Tail, there are zero new packets. If the receiver tries to read anyway, it will read old data that was already processed. The receiver must wait until the sender writes and moves Head forward.

6. TABLE: WHO UPDATES HEAD & TAIL? (SPM VS. CPM)

To avoid confusion and prevent two cores from fighting over the same pointer, there is one strict golden rule:
The Sender ONLY updates Head. The Receiver ONLY updates Tail.

Pointer Who Updates It? When It Gets Updated Update Formula Where It Lives in SPM Where It Lives in CPM
HEAD
(Write Pointer)		 SENDER ONLY Immediately AFTER the sender finishes writing a new packet into the buffer. Head = (Head + 1) % Size Stored in sender's local SPM; updated copy is mirrored or sent to receiver. Stored in shared CPM memory where both cores can see it directly.
TAIL
(Read Pointer)		 RECEIVER ONLY Immediately AFTER the receiver finishes reading and consuming a packet. Tail = (Tail + 1) % Size Stored in receiver's local SPM; updated copy is mirrored or sent to sender. Stored in shared CPM memory where both cores can see it directly.
🔑 Golden Rule of Pointers:
• Sender moves Head forward to say: "Hey, I just added a new message!"
• Receiver moves Tail forward to say: "Hey, I just finished reading this slot, you can have it back!"
